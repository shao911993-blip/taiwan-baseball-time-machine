# 驗證與迭代紀錄

## YouTube 錯誤 153 修正

- 使用者截圖確認播放器出現錯誤 153。重新讀取 YouTube 官方嵌入說明及開發文件，確認這代表缺少必要 HTTP Referer。前版直接開啟 HTML 的交付方式無法提供 HTTP 網站來源；iframe 上的 referrerpolicy 屬性本身不能補出 file:// 沒有的來源。
- 新增零 npm 依賴的 Node.js 本機伺服器 serve.cjs，以及「啟動網站.cmd」。啟動檔在使用者執行時開啟實際連接埠的瀏覽器網址；預設 4173，如已占用嘗試後續 9 個連接埠。只綁定 127.0.0.1，沒有公開部署，僅提供首頁／index.html 與健康檢查。
- HTTP 回應與 HTML meta、iframe 皆採 strict-origin-when-cross-origin。以真實本機來源讓瀏覽器傳送 Referer，沒有偽造來源、代理串流或下載影片。
- 新增開啟協定檢查：HTTP／HTTPS 仍可選集；file:// 選集改為顯示啟動步驟與對應原影片，不再先製造已知會缺來源的 iframe。新增「無法播放？」說明，保留原頻道替代入口。小螢幕播放器最低高度 200px。
- 網頁原始程式檢查新增本機／HTTP／HTTPS 分支及來源政策，共 1,660 項斷言通過。另透過真實本機 HTTP 請求完成 30 項測試，包括精確 HTML 回應、UTF-8、HEAD、Referrer-Policy、禁用寫入、專案檔案不外露、Host 驗證、連接埠占用與輸入驗證。
- 已實際啟動本機服務於 http://127.0.0.1:4173/ 。再次查詢瀏覽器清單仍為空，嘗試啟動內建瀏覽器回報「Browser is not available: iab」。因此不能宣稱已完成影片播放、瀏覽器 Referer 請求、原生啟動器自動開頁或全螢幕的實機驗證。
